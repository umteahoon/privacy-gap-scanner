# 정답지 라벨링 가이드 (논문 3.2절 정확도 평가용)

논문의 정밀도·재현율·F1은 **사람이 직접 판정한 정답지**와 시스템 판정을 비교해야 나옵니다. AI가 라벨을 채우면 "연구자 2인이 부여한 라벨"이라는 논문 서술이 거짓이 되므로, 반드시 팀원 2명이 직접 채워 주세요.

## 1. 준비된 파일

| 파일 | 용도 |
|---|---|
| `labels_annotator_sample.csv` | **이번에 라벨링할 파일.** 고정 seed(20261009)로 뽑은 무작위 15개 사이트, 166행 |
| `labels_annotator.csv` | 전체 38개 사이트, 362행 (시간이 되면 전수 라벨링) |
| `labels.csv` | 시스템 판정이 들어 있는 원본. **라벨링하는 동안 열어 보지 마세요.** |

평가자용 파일에는 시스템 판정이 없습니다. 각 행에 사이트, 사업자, 관측 도메인, 처리방침 URL이 들어 있습니다.

## 2. 절차

1. `labels_annotator_sample.csv`를 두 부 복사합니다.
   - 평가자 A: `labels_A.csv`
   - 평가자 B: `labels_B.csv`
2. **서로 결과를 보지 않고** 각자 채웁니다.
   - 평가자 A는 `annotator1` 열을, 평가자 B는 `annotator2` 열을 채웁니다.
   - 값은 `명시` / `포괄` / `미명시` 셋 중 하나입니다. 애매하면 `note` 열에 이유를 적습니다.
3. 두 파일을 합칩니다. 판정이 다른 행은 화면에 목록으로 나옵니다.
   ```bash
   node cli/merge-labels.js experiment/labels_A.csv experiment/labels_B.csv
   ```
4. 판정이 다른 행만 둘이 함께 처리방침을 다시 보고 협의합니다. 정한 값은 `experiment/labels.csv`의 `gold` 열에 적습니다. 두 사람 판정이 같은 행은 gold가 자동으로 채워집니다.
5. 평가를 실행합니다.
   ```bash
   npm run eval > experiment/eval.json
   ```
   이 결과로 논문 문장을 채웁니다.

## 3. 판정 기준

해당 사이트의 처리방침 **전체**를 읽고 판정합니다. `policy_url` 열에 주소가 있습니다.

- **명시:** 그 사업자의 이름이나 서비스명이 적혀 있습니다. 영문·한글·서비스명 모두 인정합니다.
  - 예: "Google Analytics", "카카오픽셀", "크리테오"
- **포괄:** 사업자 이름은 없지만, 그 기능을 가리키는 표현으로 고지하고 있습니다.
  - 광고 사업자의 예: "맞춤형 광고를 위해 행태정보를 수집"
  - 분석 도구의 예: "웹 로그 분석 도구 사용"
- **미명시:** 이름도 없고, 해당 기능에 대한 고지도 없습니다.

맥락도 함께 봅니다. 예를 들어 "구글"이 간편 로그인 제공자로만 적혀 있고 광고·분석 목적의 고지는 없다면, 광고 사업자로서의 Google은 **명시가 아닙니다.** 이 경우 범주 표현이 있으면 `포괄`, 없으면 `미명시`로 판정하고 note에 "로그인 맥락만 있음"이라고 적어 주세요.

## 4. 평가 결과 보기

- `undisclosedDetection`: 미명시 탐지의 정밀도/재현율/F1 (논문의 핵심 수치)
- `interAnnotatorKappa`: 두 평가자 간 일치도. 0.6 이상이면 신뢰할 만한 수준입니다.
- 오판정 목록은 터미널에 출력됩니다. 논문의 오판정 분석에 씁니다.

※ `experiment/` 아래 파일은 실명 사이트 정보가 들어 있어 git에 올리지 않습니다.
