# 정답지 라벨링 가이드 (논문 3.4절 정확도 평가용)

논문의 정밀도·재현율·F1은 **사람이 직접 판정한 정답지**와 시스템 판정을 비교해야 나옵니다. 아래 절차대로 팀원 2명이 각자 라벨링하세요. (약 1~2시간)

## 1. 파일

`experiment/labels.csv`를 엑셀로 엽니다. 한 행은 "사이트–추적 사업자" 한 쌍입니다.

| 열 | 내용 |
|---|---|
| site, entity, hosts | 어느 사이트에서 어느 사업자에게 실제 요청이 나갔는지 |
| system_status | 시스템 판정 (**라벨링할 때는 이 열을 가리고 보세요**) |
| annotator1 | 팀원 A의 판정 |
| annotator2 | 팀원 B의 판정 (A의 결과를 보지 않고 독립적으로) |
| gold | 두 사람의 판정이 다를 때 협의해서 정한 최종값 (같으면 비워둬도 됨) |
| note | 판단 근거나 특이사항 |

## 2. 판정 기준

해당 사이트의 개인정보처리방침 전체를 읽고 판정합니다. 결과 JSON의 `policy.url`에 처리방침 주소가 있습니다.

- **명시**: 그 사업자 이름이나 서비스명이 적혀 있음 (예: "Google Analytics", "카카오픽셀", "크리테오"). 영문·한글·서비스명 어느 것이든 인정합니다.
- **포괄**: 사업자 이름은 없지만, 그 기능을 가리키는 표현으로 고지함 (예: 광고 사업자 → "맞춤형 광고를 위해 행태정보를 수집", 분석 도구 → "웹 로그 분석 도구 사용")
- **미명시**: 이름도, 해당 기능에 대한 고지도 없음

애매한 경우는 note에 이유를 적고, 두 사람이 협의해 gold를 정합니다.

## 3. 평가 실행

```bash
npm run eval > experiment/eval.json
```

- `undisclosedDetection`: 미명시 탐지의 정밀도/재현율/F1 (논문의 핵심 수치)
- `interAnnotatorKappa`: 두 평가자 간 일치도 (0.6 이상이면 신뢰할 만함)
- 오판정 목록은 터미널에 출력되며, 논문의 오류 분석에 활용합니다.

`experiment/eval.json`이 생기면 `python paper/build_paper.py`를 다시 실행할 때 수치가 논문에 자동으로 들어갑니다.

> 시간이 부족하면 전체 대신 무작위 15~20개 사이트만 라벨링해도 됩니다. 이 경우 논문에 "무작위 표본 n개 사이트"라고 명시하세요.
