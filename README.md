# Privacy Gap Scanner

> 개인정보처리방침에 **적힌 것**과 웹사이트가 **실제로 하는 일**을 대조합니다.

웹사이트 주소를 입력하면 실제 브라우저로 사이트를 열어 데이터를 받아가는 외부 사업자(광고·분석 트래커)를 찾아내고, 각 사업자가 그 사이트의 개인정보처리방침에 고지되어 있는지 하나씩 판정합니다.

한국인공지능융합기술학회(KAICTS) 학술대회 논문 「개인정보처리방침과 실제 브라우저 동작 간 불일치 탐지를 위한 다층 교차 대조 시스템」의 구현체입니다.

## 1. 왜 만들었나

웹사이트에는 광고·분석 스크립트가 마케팅 목적에 따라 수시로 추가됩니다. 반면 개인정보처리방침은 몇 년 전에 작성된 그대로인 경우가 많아, 문서와 실제 동작이 어긋나기 쉽습니다.

기존 연구는 이 문제를 부분적으로만 다뤘습니다. 처리방침 문서만 분석하거나(Polisis), 트래커 실태만 측정하거나(OpenWPM), 모바일 앱만 대상으로 했습니다(PoliCheck). 웹을 다룬 연구(Libert, 2018)는 영문 사이트와 해외 트래커 목록을 기준으로 해서 **네이버·카카오 같은 국내 사업자와 한국어 처리방침**에는 그대로 적용하기 어렵습니다.

이 프로젝트는 한국어 처리방침과 실제 브라우저 동작을 **사업자 단위로 1:1 대조**합니다.

## 2. 주요 기능

- **URL 하나로 검사:** 40초~2분 안에 사이트별 리포트가 나옵니다.
- **사업자별 판정:**
  - **명시:** 처리방침에 사업자·서비스명이 직접 적혀 있음
  - **포괄 고지:** "맞춤형 광고", "행태정보"처럼 범주로만 적혀 있음
  - **미명시:** 어디에도 없음
- **근거 제시:** 판정의 근거가 된 처리방침 문장을 원문 그대로 보여줍니다.
- **정량 지표:** 약관 명시율, Gap 지수, A~E 등급, 제3자 쿠키 수
- **실험 대시보드:** 국내 웹사이트 76곳 실증 실험 결과를 익명 집계로 보여줍니다.
- **국내 트래커 지식베이스:** 해외 목록에 없는 국내 광고·분석 사업자(네이버, 카카오, 모비온, 와이더플래닛, 데이블, 에이스카운터 등)를 포함한 52개 사업자

## 3. 어떻게 만들었나

### 3.1 전체 구조

```
                  ┌───────────────────────────┐
  URL 입력 ──▶   │ ① 런타임 동작 수집 계층        │  헤드리스 Chromium(Playwright)
                  │   외부 요청 · 쿠키 · Storage   │  robots.txt 확인, 사설망 요청 차단
                  └─────────────┬─────────────┘
                                │
                  ┌─────────────▼─────────────┐
                  │ ② 처리방침 추출 계층          │  링크/모달/목록형 페이지 탐지
                  │   본문 추출 · 정규화           │  (선택) LLM 구조화 추출
                  └─────────────┬─────────────┘
                                │
                  ┌─────────────▼─────────────┐
                  │ ③ 교차 대조 엔진              │  도메인 → 사업자 매핑
                  │   명시 / 포괄 / 미명시 판정    │  Coverage · Gap 지수 · 등급
                  └─────────────┬─────────────┘
                                ▼
                     Netlify Blobs 저장 → React 리포트
```

### 3.2 ① 런타임 동작 수집 (`lib/scan.js`)

1. 방문 전에 `robots.txt`(RFC 9309)를 확인합니다. 금지된 경로면 검사하지 않습니다.
2. Playwright로 Chromium을 띄웁니다. User-Agent에는 `PrivacyGapScanner/1.0` 식별자를 붙입니다.
3. 메인 페이지와 같은 사이트의 내부 링크 2개를 차례로 열고, 스크롤해서 지연 로딩되는 스크립트까지 실행시킵니다.
4. 이 과정에서 발생하는 모든 HTTP(S) 요청의 **도메인, 경로, 쿼리 파라미터 이름**을 가로채 기록합니다. 쿠키는 **이름과 도메인만** 기록하고 값은 저장하지 않습니다.
5. 응답이 403이거나 봇 확인 페이지가 나오면 우회하지 않고 중단합니다.

### 3.3 ② 처리방침 추출 (`lib/policy.js`, `lib/llm.js`)

- 페이지 하단에서 "개인정보처리방침" 링크를 정규식으로 찾습니다.
- 새 창, 모달, iframe, 여러 버전이 나열된 목록형 페이지까지 따라가 본문을 추출합니다.
- 본문 길이가 충분하고 "개인정보", "수집·이용·제공·위탁" 같은 표현이 있을 때만 처리방침으로 인정합니다.
- 본문은 공백과 기호를 제거한 정규화 문자열로 바꿉니다. 이때 **원문 위치 대응표**를 함께 만들어 두어, 판정 근거를 원문 그대로 잘라 보여줄 수 있습니다.
- **(선택)** `ANTHROPIC_API_KEY`가 설정되어 있으면 Claude에 JSON 스키마를 지정해 고지된 사업자명, 역할(제3자 제공·위탁·행태정보), 포괄 고지 문구를 추가로 추출합니다. 키가 없으면 규칙 기반 판정만 사용합니다.

### 3.4 ③ 교차 대조 알고리즘 (`lib/trackers.js`, `lib/disclosure.js`, `lib/score.js`)

1. **사업자 매핑:** 요청 호스트를 지식베이스의 도메인 규칙과 대조합니다. 가장 길게 일치하는 규칙을 고르며, 경로까지 볼 수 있습니다. 예: `wcs.naver.net` → 네이버 / 웹 분석, `google.com/pagead` → Google / 광고
2. **자사 제외:** 사이트 운영 주체와 같은 사업자는 제외합니다. 예: 네이버 사이트의 네이버 요청
3. **고지 대상 선별:** 광고, 분석, 소셜, 세션 녹화, 광고 성과 측정, 마케팅 자동화 사업자만 "추적 사업자"로 판정합니다. CDN, 폰트, 결제, 지도는 참고로만 보여줍니다.
4. **3단계 판정:** 각 추적 사업자에 대해 차례로 확인합니다.
   - 사업자 별칭(예: `구글애널리틱스`, `카카오픽셀`, `criteo`)이 본문에 있으면 **명시**
   - 없으면 해당 기능의 범주 표현(예: 광고 → `맞춤형광고`, `행태정보` / 분석 → `웹로그분석`)이 있는지 보고, 있으면 **포괄 고지**
   - 둘 다 없으면 **미명시**
5. **지표 계산:** 추적 사업자 수를 N, 명시·포괄·미명시를 각각 E, V, U라 할 때

| 지표 | 계산 | 의미 |
|---|---|---|
| 약관 명시율 | E / N | 이름까지 고지된 비율 |
| Gap 지수 | (U + 0.5V) / N | 0 = 완전 고지, 1 = 전부 미고지 |
| Gap 등급 | U 기준 | A(U=0, V=0) · B(U=0, V>0) · C(U≤2) · D(U≤5) · E(U≥6). 쿠키를 만들면서 쿠키 고지가 없으면 한 단계 하향 |

### 3.5 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 프론트엔드 | React 19, React Router, Vite |
| 백엔드 | Netlify Functions (검사 요청 함수 + 최대 15분 실행되는 백그라운드 함수) |
| 저장소 | Netlify Blobs (Netlify 기본 포함, 별도 DB·키 불필요) |
| 브라우저 자동화 | Playwright, `@sparticuz/chromium-min` (서버리스용 Chromium을 실행 시 내려받아 함수 용량 제한 회피) |
| 도메인 분석 | `tldts` (`.co.kr` 같은 공용 접미사를 고려한 도메인 판별) |
| LLM (선택) | Anthropic Claude API (`@anthropic-ai/sdk`) |

### 3.6 요청 처리 흐름

```
브라우저 ──POST /api/scan──▶ scan-create 함수
                               ├ URL 검증 · SSRF 차단 · 요청 횟수 제한
                               ├ Blobs에 작업 등록 (status: queued)
                               └─▶ scan-worker 백그라운드 함수 호출 (비밀키 검증)
                                     └ 검사 실행 → 진행 상황/결과를 Blobs에 기록
브라우저 ──GET /api/scan/:id (2.5초마다)──▶ scan-get 함수 → 진행 상황 / 리포트
```

## 4. 실행 방법

### 4.1 준비물

- Node.js 20 이상
- Git

### 4.2 로컬 실행

```bash
git clone https://github.com/umteahoon/privacy-gap-scanner.git
cd privacy-gap-scanner
npm install
npx playwright install chromium
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다.

- 로컬에서는 Vite 개발 서버가 Netlify Functions와 같은 API(`/api/scan`, `/api/scan/:id`)를 메모리 저장소로 흉내 냅니다. 따라서 `npm run dev`만으로 검사 기능까지 전부 동작합니다.
- 서버를 재시작하면 검사 결과가 사라집니다.
- 인터넷이 불안정한 발표장에서는 오프라인 백업 시연용으로도 쓸 수 있습니다.

### 4.3 명령줄에서 사이트 하나 검사

```bash
node cli/scan.js https://www.example.co.kr
node cli/scan.js https://www.example.co.kr --policy https://www.example.co.kr/privacy --out result.json
```

### 4.4 LLM 추출 사용 (선택)

```bash
# macOS / Linux
export ANTHROPIC_API_KEY=sk-ant-...
# Windows PowerShell
$env:ANTHROPIC_API_KEY="sk-ant-..."
```

## 5. Netlify 배포

1. 이 저장소를 Netlify에서 **Add new site → Import an existing project**로 연결합니다. 빌드 설정은 `netlify.toml`이 자동으로 적용합니다.
2. **Site configuration → Environment variables**에 아래 값을 추가합니다.

| 변수 | 필수 | 설명 |
|---|---|---|
| `SCAN_WORKER_SECRET` | ✅ | 내부 워커 호출 보호용 임의의 긴 문자열 (예: `openssl rand -hex 32` 결과). IP 해시에도 사용 |
| `ANTHROPIC_API_KEY` | | LLM 약관 추출 사용 시 |
| `SCAN_LIMIT_PER_IP_HOUR` | | IP당 시간당 검사 횟수 (기본 10) |
| `SCAN_LIMIT_PER_DAY` | | 전체 일일 검사 횟수 (기본 300) |
| `SCAN_RETENTION_DAYS` | | 검사 결과 보관 일수 (기본 30) |

3. 배포하면 Netlify Blobs는 자동으로 활성화됩니다. 따로 설정할 것은 없습니다.

> 첫 검사는 서버리스용 Chromium 팩(약 60MB)을 내려받느라 10~20초 더 걸릴 수 있습니다.

## 6. 실증 실험 재현

```bash
cp experiment/sites.example.csv experiment/sites.csv   # 검사할 사이트 목록 작성 (category,url,policy_url)
npm run batch -- --concurrency 4                       # 일괄 스캔 (원시 관측 데이터 포함 저장)
npm run batch -- --reanalyze                           # 지식베이스·규칙 수정 후 저장된 데이터로 재판정만 수행
npm run eval > experiment/eval.json                    # 정답지 라벨링 후 정밀도/재현율/F1, Cohen's κ 계산
```

- `experiment/results/*.json`: 사이트별 상세 결과 (로컬 전용)
- `experiment/summary.csv`: 사이트별 지표 요약 (로컬 전용)
- `experiment/labels.csv`: 정답지 라벨링 양식. 작성법은 [LABELING_GUIDE.md](experiment/LABELING_GUIDE.md) 참고
- `public/experiment-summary.json`: 웹 "실험 결과" 페이지용 **익명 집계**

> 실제 사이트명이 들어간 실험 원자료(사이트 목록, 사이트별 결과, 처리방침 원문)는 특정 기업에 대한 평가로 오해되거나 저작권 문제가 생길 수 있어 저장소에 올리지 않습니다(`.gitignore`).

## 7. 법적·윤리적 준수 사항

| 항목 | 구현 |
|---|---|
| 접근 정책 준수 | robots.txt(RFC 9309)가 금지하면 검사하지 않습니다. 처리방침이 다른 도메인에 있으면 그 도메인의 robots.txt도 확인합니다. 403·봇 확인 페이지가 나오면 우회하지 않고 중단합니다 |
| 신원 공개 | User-Agent에 `PrivacyGapScanner/1.0` 식별자를 명시합니다 |
| 최소 접근 | 비로그인 상태로 메인 페이지와 내부 링크 최대 2개만 열람합니다. 로그인·회원가입·폼 입력·결제 경로는 방문하지 않습니다 |
| 대상 부하 최소화 | 같은 URL은 30분간 결과를 재사용합니다. IP당·일일 요청 횟수를 제한합니다 |
| 데이터 최소화 | 대상 사이트의 쿠키 값과 요청 파라미터 값은 저장하지 않습니다 (이름·도메인만 저장) |
| 이용자 개인정보 | IP 원문은 저장하지 않고 HMAC 값만 1시간 동안 사용합니다. 검사 결과는 30일 후 자동 삭제됩니다 |
| 결과 공개 범위 | 공개 목록이 없습니다. 추측할 수 없는 UUID 주소로만 조회할 수 있고, `noindex`로 검색 노출을 차단합니다 |
| 명예훼손 방지 | 결과는 "기술적 불일치 탐지"이며 법률 판단이 아님을 화면에 명시합니다. 실험 결과는 사이트명을 익명화합니다 |
| 이용 동의 | 검사 전 이용 안내 동의 체크가 필수입니다 |

## 8. 보안

- **SSRF 방지:**
  - IP 직접 입력과 `localhost` 등 로컬 도메인을 거부합니다.
  - DNS 조회 결과가 사설망이면 거부합니다. 예: `localtest.me` → 127.0.0.1
  - 브라우저의 리다이렉트·하위 요청 중 사설 IP나 localhost로 가는 요청도 차단합니다.
- **내부 워커 보호:** 백그라운드 워커는 `SCAN_WORKER_SECRET` 헤더를 상수 시간 비교로 검증합니다.
- **입력 제한:** 요청 본문 8KB, URL 2048자, http/https만 허용하며, URL에 계정 정보가 들어 있으면 거부합니다.
- **보안 헤더:** CSP, HSTS, X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy (`netlify.toml`)
- **XSS:** 외부에서 가져온 문자열은 React 텍스트로만 렌더링하고, 링크는 http/https일 때만 만듭니다.
- **비밀값:** 모든 키는 환경변수로만 관리하며 클라이언트 번들과 저장소에 포함하지 않습니다.

## 10. 한계와 향후 과제

- **맥락 미구분:** 같은 사업자가 다른 맥락으로 기재된 경우를 구분하지 못합니다. 예를 들어 간편 로그인 제공자로 "구글"만 적혀 있어도 Google 광고 추적까지 명시로 판정됩니다. → LLM 기반 역할 인식 판정으로 개선할 예정입니다.
- **지식베이스 누락:** 지식베이스에 없는 도메인은 "미분류"로만 표시되고 판정에서 빠집니다. 따라서 미명시 수치는 하한값으로 해석해야 합니다.
- **비로그인 범위:** 비로그인 공개 페이지만 검사하므로, 로그인 이후나 동의 배너를 수락한 이후의 동작은 다루지 않습니다.
- **처리방침 형식:** 처리방침이 이미지나 첨부 파일로만 제공되면 본문을 읽을 수 없습니다.
- **향후 과제:** 동의 배너 전후 동작 비교, 모바일 앱 분석으로 확장할 계획입니다.
